# 1. 整个实验的脑图

训练阶段：

```text
Human
↓
Leader
↓
Follower
↓
┌─────────────────────────────┐
│ Real-world interaction      │
│                             │
│ fixed RGB                   │
│ handeye RGB                 │
│ follower joint state        │
│ expert action               │
└──────────────┬──────────────┘
               ↓
        LeRobot Dataset
               ↓

               ↓

```

如果以后进入推理：

```text

↓
camera + current state
↓
Trained Policy
↓
action
↓
Follower
↓

↓
Policy ...
```

本次 5-demo 课堂实验只要求跑到：

```text
Training starts
→ step + loss
```

# 2. Imitation Learning 是什么

模仿学习的核心：

```text
Expert Demonstration
↓
Observation → Expert Action
↓
learn policy π(a | o)
```

这里不是人为写：

```python
if cube_is_left:
    shoulder_pan += 5
```

而是让模型从大量配对数据中学习：

```text
给定观察 o
应该产生怎样的动作 a
```

---

# 3. Leader、Follower 与 Human Demonstration

## Leader

人手操作的主臂。

职责：

```text
把人的运动意图
转换成可记录的机器人控制动作
```

## Follower

真正与物体交互的机械臂。

采集：

```text
Human
↓
Leader
↓
Follower
```

以后推理：

```text
Policy
↓
Follower
```

所以 Leader 是：

```text
数据采集接口
```

不是最终部署策略的一部分。

---

# 4. Observation、State、Action

## Observation

策略能看到的信息。

本实验主要包括：

```text
observation.images.fixed
observation.images.handeye
observation.state
```

## State

机器人本体状态。

课程数据中：

```text
observation.state ∈ R^6
```

对应：

```text
shoulder_pan
shoulder_lift
elbow_flex
wrist_flex
wrist_roll
gripper
```

## Action

专家给出的控制目标：

```text
action ∈ R^6
```

训练的核心监督信号就是：

```text
Observation
→
Expert Action
```

---

# 5. 为什么 action 和 state 不完全相等

例如某一帧：

```text
action:
目标关节位置

state:
真实测量关节位置
```

由于：

```text
控制周期
舵机动态
机械负载
通信延迟
控制误差
```

所以：

```text
action_t ≠ state_t
```

这是正常的。

如果二者永远完全相同，反而应该检查记录逻辑。

---

# 6. Episode 是什么

Episode：

> 从任务开始到任务结束的一段完整时序轨迹。

一个 Episode 不是一个静态样本。

它包含：

```text
t0:
image + state + action

t1:
image + state + action

t2:
image + state + action

...

tN:
image + state + action
```

5 demos 意味着：

```text
5 条完整 Episode
```

而不是只有 5 个训练样本。

---

# 7. FPS 和帧数

本实验：

```text
30 FPS
```

如果一条 Episode 有：

```text
300 frames
```

约等于：

```text
10 seconds
```

5 条 Episode 的总帧数可能是一千多帧。

训练 sample 会从这些时序帧中构造。

---

# 8. 为什么一个 Episode 同时有 Parquet 和 MP4

机器人数据有两类：

## 结构化数值

适合表格式时序存储：

```text
state
action
timestamp
frame_index
episode_index
```

使用：

```text
Parquet
```

## 图像

一帧一帧保存成 PNG 会产生大量小文件。

所以使用：

```text
MP4
```

分别保存：

```text
fixed
handeye
```

训练时再根据 timestamp 解码需要的 RGB frame。

# 9. Metadata 为什么重要

```text
meta/info.json
```

描述整个 Dataset：

```text
robot_type
total_episodes
total_frames
fps
features
data_path
video_path
```

`episodes.jsonl`：

```text
每条 Episode 的信息
```

`episodes_stats.jsonl`：

```text
每条 Episode 的统计信息
```

`tasks.jsonl`：

```text
任务文本及 task index
```

Metadata 不是“说明文件”。

它是 Dataset 索引系统的一部分。

# 10. 真机数据为什么不用 ManiSkill replay

ManiSkill：

```text
Motion Planner
↓
仿真轨迹
↓
replay_trajectory.py
↓
换 observation/control representation
```

SO-101 真机：

```text
传感器 + Follower state + Leader action
↓
record
↓
当场记录最终训练需要的 observation/action
```

因此真机的：

```text
record
```

已经完成主要结构化。

这也是：

```text
ManiSkill .h5 Demo
↔
SO-101 Parquet + MP4
```

之间的重要差异。

---

# 11. “数据处理”到底发生在哪里

真机不是“不处理数据”。

而是分成两层。

## 第一层：Record-time processing

```text
raw camera frames
raw robot states
raw teleoperation actions
↓
episode organization
timestamp
index
video encoding
parquet writing
metadata writing
↓
LeRobot Dataset
```

## 第二层：Training-time processing

```text
LeRobot Dataset
↓
query timestamps
↓
decode video
↓
RGB Tensor
↓
read state/action
↓
temporal sampling
↓
normalization
↓
Batch
↓
Model
```

所以没有额外 `convert.py`，不代表没有数据处理。

---

# 12. DataLoader 是什么

DataLoader 将：

```text
Dataset
↓
sample
↓
Batch
↓
GPU
```

它负责重复取样。

真实训练链：

```text
LeRobotDataset.__getitem__()
↓
读取数值数据
↓
查询对应视频帧
↓
形成 sample
↓
DataLoader 合并 Batch
↓
Policy
```

很多训练错误其实发生在：

```text
Model forward 之前
```

例如：

```text
视频无法解码
timestamp 对不上
Dataset metadata 不完整
```

---

# 13. PyAV 是什么

PyAV：

> FFmpeg 的 Python binding。

课程中负责：

```text
MP4
↓
decode
↓
RGB frame
↓
Tensor
```

它不是：

```text
Diffusion Policy
ResNet
机器人控制器
```

只是视频 I/O 层。

训练参数：

```text
--dataset.video_backend=pyav
```

决定“视频怎么读”，不改变“机器人怎么学”。

---

# 14. TorchCodec 和 PyAV

二者都可以承担：

```text
MP4 → RGB
```

课程选择 PyAV 是工程稳定性选择。

结构：

```text
            MP4
             │
      ┌──────┴──────┐
      ↓             ↓
  TorchCodec       PyAV
      │             │
      └──────┬──────┘
             ↓
         RGB Tensor
             ↓
       Vision Encoder
```

# 15. Diffusion Policy 在学什么

传统确定性 policy 可以写成：

```text
a = π(o)
```

Diffusion Policy 更接近学习：

```text
p(action sequence | observation)
```

它通过扩散/去噪过程生成连续动作序列。

直观理解：

```text
随机噪声动作轨迹
↓
结合当前 observation
↓
一步步去噪
↓
形成合理 action sequence
```

这使它适合处理：

```text
连续控制
多模态动作
平滑轨迹
```

# 16. Vision Backbone：ResNet18

课程已验证配置中：

```text
vision_backbone = resnet18
```

作用：

```text
RGB image
↓
ResNet18
↓
visual feature
```

两路相机：

```text
fixed
handeye
```

如果：

```text
use_separate_rgb_encoder_per_camera = False
```

则表示两路图像共享同一套视觉编码器参数。

---

# 17. pretrained_backbone_weights=None 是什么

```text
pretrained_backbone_weights = None
```

表示：

```text
ResNet18 没有加载 ImageNet 预训练权重
```

不要与：

```text
use_imagenet_stats = True
```

混淆。

后者只是：

```text
图像 normalization 使用 ImageNet 风格 mean/std
```

两者不是一回事。

---

# 18. Conditional 1D U-Net

Diffusion Policy 的动作生成网络可理解为：

```text
Observation condition
+
Noisy action trajectory
+
Diffusion timestep
↓
Conditional 1D U-Net
↓
预测噪声/去噪方向
↓
Action trajectory
```

课程此前运行配置中出现过：

```text
down_dims = [512, 1024, 2048]
```

这解释了为什么视觉版 Diffusion Policy 参数量可能很大。

---

# 19. Horizon

课程配置曾使用：

```text
horizon = 16
```

含义：

```text
一次模型内部处理/生成长度 16 的动作时间窗口
```

不是：

```text
只预测下一帧一个 action
```

---

# 20. n_obs_steps

例如：

```text
n_obs_steps = 2
```

表示使用：

```text
observation at t-1
+
observation at t
```

提供短时动态信息。

---

# 21. n_action_steps

例如：

```text
n_action_steps = 8
```

表示 policy 可以预测更长 horizon，但每轮只执行其中的一段动作，然后重新观察。

这就是：

```text
Action Chunking
+
Receding Horizon Execution
```

---

# 22. DDPM timestep 不是机械臂 timestep

Diffusion 的：

```text
100 denoising timesteps
```

是：

```text
生成模型内部的去噪步骤
```

不是：

```text
机器人执行 100 个控制周期
```

两种 timestep 必须区分。

---

# 23. Offline Training

本实验训练是：

```text
固定 Dataset
↓
反复采样
↓
拟合 Expert behavior
```

机器人训练过程中不与真实世界互动。

因此叫：

```text
Offline Imitation Learning
```

---

# 24. Rollout 和 Offline Training 的区别

Offline：

```text
固定数据
→ 模型学习
```

Rollout：

```text
Policy 输出 action
↓
改变真实世界
↓
产生新的 observation
↓
Policy 再输出 action
```

Rollout 中错误会累积。

这解释了：

```text
training loss 很低
```

仍然可能：

```text
真机失败
```

---

# 25. Distribution Shift

如果训练数据中 cube 都在区域 A：

```text
A
```

测试放到区域 B：

```text
B
```

而 B 没被 Demonstration 覆盖，则策略可能失败。

这是：

```text
Distribution Shift
Covariate Shift
```

模仿学习非常核心的问题。

---

# 26. 为什么 5 demos 只能做教学 Smoke Test

5 条 Demonstration 能证明：

```text
record works
Dataset works
video decode works
DataLoader works
Policy forward works
loss/backward works
```

不能证明：

```text
generalization
robustness
real-world success rate
```

正式实验需要更多：

```text
数据数量
初始位置多样性
动作质量
场景覆盖
独立评估
```

---

# 27. 为什么不能只删一个坏 Parquet

Episode 是多文件关联对象：

```text
episode_000003.parquet
+
fixed/episode_000003.mp4
+
handeye/episode_000003.mp4
+
episodes.jsonl entry
+
episodes_stats.jsonl entry
+
global indices
```

因此：

```bash
rm episode_000003.parquet
```

会破坏一致性。

正确思路：

```text
录制时重录
或
生成新的 clean Dataset
```

# 37. 为什么 by-id 很重要

```text
/dev/ttyACM0
```

是动态编号。

```text
/dev/serial/by-id/
```

根据设备唯一标识建立稳定链接。

相机同理：

```text
/dev/v4l/by-id/
```

这是做真实机器人时非常重要的 Linux 工程知识。

# 38. 从 ManiSkill 到真机的对应关系

| ManiSkill | SO-101 真机 |
|---|---|
| Simulator | Real World |
| Panda | SO-101 Follower |
| Motion Planner | Human + Leader |
| Sim State | Camera + Joint State |
| Automatic Reset | Manual Reset |
| `.h5` Demo | Parquet + MP4 |
| Replay/Convert | Record-time structuring + Loader |
| Environment Success | Human-defined success |
| Diffusion Policy | Diffusion Policy |
| Sim Rollout | Real Robot Rollout |

核心主线不变：

```text
Demonstration
↓
Dataset
↓
Policy
↓
Rollout
↓
Evaluation
```

# 39. 一张表理解整个数据流

| 阶段 | 输入 | 输出 | 关键代码 |
|---|---|---|---|
| Teleoperation | Human motion | Follower action | `control_robot.py` |
| Recording | camera/state/action | LeRobot Dataset | `control_robot.py` |
| Structured numeric data | state/action/time | Parquet | dataset recording |
| Visual data | RGB frames | MP4 | camera/video writer |
| Dataset loading | Parquet + MP4 + metadata | sample | `lerobot_dataset.py` |
| Video decoding | MP4 + timestamp | RGB Tensor | `video_utils.py` |
| Training | Batch | policy update | `train.py` |
| Policy | observation | action sequence | Diffusion implementation |
| Future rollout | live observation | real action | `control_robot.py` |
